Stored procedures (transactions)

Both procedures are all-or-nothing. sp_create_trip rolls the demo back by default so no rows are left behind; sp_book_room keeps its reservation so a second call can show the double-booking rejection.

sp_create_trip

Creates a trip, adds the owner as a member with role 'owner', and one itinerary_days row per date.

sp_book_room

Locks the room row with FOR UPDATE, inserts the reservation, and sets the confirmation code. Booking the same room twice on overlapping dates is rejected by the trigger.

Destination recommendations

Scores each destination a user has not visited, out of 100: quality 30, crowd 15, wishlist 15, personal taste 20, in-season 20. The repository documents this layer (script 07) but does not include it, so the model is implemented in app/recommender.py against the existing tables.
